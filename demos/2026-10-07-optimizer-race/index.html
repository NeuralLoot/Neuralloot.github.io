The mechanism

Every optimizer here gets the exact same thing each step: the gradient g = ∇f(θ) at its current point. The only difference is what it does with it. These are the exact update rules running in this page (per coordinate, ε = 10⁻⁸).

SGD

Step straight downhill, scaled by η. Stable only while η is below 2 / (largest curvature); past that it oscillates and blows up.

θ ← θ − η·g

Momentum (heavy ball)

Keep a running velocity. Consistent directions accumulate speed; directions that flip sign partly cancel out.

v ← β·v + g
θ ← θ − η·v

RMSProp

Divide each coordinate by a running RMS of its own gradients, so steep and shallow directions take similar-sized steps.

s ← ρ·s + (1−ρ)·g²
θ ← θ − η·g / (√s + ε)

Adam

Momentum on the numerator, RMSProp on the denominator, plus bias correction for the zero-initialized averages.

m ← β₁·m + (1−β₁)·g
s ← β₂·s + (1−β₂)·g²
m̂ = m/(1−β₁ᵗ),  ŝ = s/(1−β₂ᵗ)
θ ← θ − η·m̂ / (√ŝ + ε)
Find the SGD cliffOn the bowl, curvature is 1 in x and 25 in y, so SGD is stable only for η < 2/25 = 0.08. Push the SGD slider past 0.08 and watch it zig-zag out of the valley.
Escape the saddleOn the saddle, the start sits at x = 0.001, almost exactly on the ridge. SGD's x-gradient is tiny there; the adaptive methods normalize it and roll off much sooner.
Kill the memorySet Momentum β to 0 and it becomes plain SGD. Set Adam β₁ to 0 and it becomes RMSProp with bias correction (β₂ playing the role of ρ).

Everything on this page is computed live in your browser from the formulas above. The surfaces are standard optimization test functions, not a real network's loss. Which optimizer "wins" depends heavily on the learning rate, the surface, and the start, so treat this as intuition for the mechanism, not a benchmark.
