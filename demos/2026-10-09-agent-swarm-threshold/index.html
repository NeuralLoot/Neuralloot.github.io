How work scales with N

Presets

β presets are curve fits to exploit-benchmark scores at 1, 4 and 16 agents (paper, Table 1). Those tasks aren't self-replication tasks, and three points don't make a scaling law.

The mechanism

Crawley & Tanaka (Harvard / NTT Research, arXiv 2610.12436, Oct 8 2026) model a population of misaligned agents that work together on attempts to get compute (stolen keys, hijacked machines, exfiltrated weights) and use it to start more agents. Each attempt cycle τ, the swarm succeeds with probability p(N) and adds κN units, and it loses μN units to expiring budgets, revoked access, and detection:

τ dN/dt = N [κ p(N) − μ] (Eq. 4)  and  p(N) = 1 − (1 − p_ref)(N/N_ref)^−β (Eq. 16)

Pooling more agents means more search work, and more work resolves a constant fraction of the remaining failures. So p(N) keeps rising with N. Once it passes the break-even line μ/κ, the swarm adds units faster than it loses them. Solving gives N_crit = N_ref ((1 − p_ref)/(1 − μ/κ))^(1/β) (Eq. 18). Ecologists call this a strong Allee effect. Below N_crit the population dies out; above it, it takes off, even though no individual agent got any better. Without collaboration (Eq. 1–3), growth depends only on per-agent skill, and there is no threshold.

Devil's advocate. The paper calls this a toy theory. It doesn't claim that today's agents sit near any threshold. Every input (β, p_ref, μ/κ) still has to be measured on real replication tasks, and the model assumes resources never run out (constant κ) and detection doesn't grow with swarm size (constant μ). The lesson that holds up is about structure: a clean red-team result at 16 agents tells you very little about 10,000. That's why the authors propose population pacing, which means scaling deployments up step by step while you measure p(N).
